# LAN addressing and DNS

Lab NIC 2 uses VirtualBox internal network `classroom-isolated`. No host-only adapter, host DNS edit or router DHCP edit is required. The Windows test VM uses 192.168.77.20/24, DNS 192.168.77.10, no gateway on NIC 2. Keep its NAT NIC disabled in Windows during domain tests so public DNS cannot be selected. Lab values must not overlap the host LAN/VPN. Server SSH/apt still use NAT NIC 1, Samba only NIC 2 and loopback.

For production, use a wired bridged NIC and a static address outside the router's dynamic lease pool. Confirm the classroom subnet and actual free address with the network owner: a ping failure does not prove an address is free. Exclude/reserve that address on the router, check existing leases and duplicate-IP detection. A reservation alone is insufficient when its MAC differs from a recreated VM; exclude the address from dynamic allocation.

Use an AD subdomain of a name owned by the school, e.g. `ad.school.example` as a documentation placeholder. Never copy a placeholder into the real domain. NetBIOS name must be 15 or fewer simple characters. Plan names before provisioning; changing AD DNS names is not an ordinary config edit.

The router remains DHCP server and internet gateway. For joined Windows clients, DHCP option 6 must list **only the Samba DC's IP** (or another AD-aware DC in future). Option 15 can be the AD DNS suffix. Do not add router/ISP/public DNS as a client secondary: it intermittently breaks AD lookup. The DC forwards external DNS to the configured reachable upstream resolver, avoiding a forwarding loop. If the router cannot scope DNS to classroom PCs, use the client joining script to set static DNS on those PCs; do not modify the teacher laptop without permission. Keep the teacher host usable when the VM is down.

This is a single-subnet design. `gateway` is a documented LAN planning value, not automatically installed as guest default: NAT remains the guest default for updates. Replies to same-subnet clients use NIC 2. Clients in another subnet require a separately reviewed route/firewall design; do not expand this project to routed/VLAN clients by guessing routes. AP client isolation must be off for classroom clients, and switches/APs must permit inter-client traffic. No AD ports should be exposed to the internet or port-forwarded on the router.

If a LAN firewall exists, allow between classroom subnet and DC: TCP/UDP 53 DNS, TCP/UDP 88 Kerberos, UDP 123 NTP, TCP 135 RPC, TCP/UDP 389 LDAP, TCP 445 SMB, TCP/UDP 464 password changes, TCP 636 LDAPS when used, TCP 3268/3269 global catalog, and TCP 49152-65535 dynamic RPC. Legacy NetBIOS ports 137/138 UDP and 139 TCP may be needed for legacy discovery; modern SMB/domain joining should use DNS/445. Restrict SSH to administrators. This repository does not rewrite host/router firewalls or turn on a guest firewall that would disrupt Vagrant; review the LAN perimeter before rollout.

Check from the Windows pilot: `Resolve-DnsName -Type SRV _ldap._tcp.dc._msdcs.YOUR_DOMAIN -Server YOUR_DC_IP`, `Test-NetConnection YOUR_DC_IP -Port 445`, and time agreement within minutes. Stable DNS, time, and reachable SMB/RPC are prerequisites for joining.
