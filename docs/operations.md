# Обслуговування шкільного сервера

## Резервна копія

Зберігайте повну копію VM на окремому фізичному диску з шифруванням. Вона містить учнівські файли, домен, політики, ключі агентів, приватний ключ центру сертифікації та журнал дій. Доступ до диска надайте лише адміністраторам. Тримайте ще одну перевірену копію від’єднаною від хоста.

У комплекті є `Backup-SchoolVM.ps1`. На Windows-хості розпакуйте архів у папку адміністратора. У PowerShell від імені адміністратора виконайте команди нижче з папки зі сценарієм. Замініть `E:\SchoolBackups` на каталог резервного диска.

```powershell
$tools = "$env:ProgramFiles\School Class Manager\Host"
New-Item -ItemType Directory -Force $tools, 'E:\SchoolBackups' | Out-Null
Copy-Item .\Backup-SchoolVM.ps1 $tools
& "$tools\Backup-SchoolVM.ps1" -VMName school-server -Destination E:\SchoolBackups
```

Сценарій коректно зупиняє VM, експортує її та знову запускає, якщо на початку вона працювала. Поки триває експорт, домен, панель і диск H: недоступні. Оберіть час поза уроками. Завершений каталог має назву на зразок `school-server-20261127-010000`. Суфікс `.partial` означає незавершену копію.

Після першої успішної перевірки налаштуйте щоденне виконання на хості. Для прикладу нижче диск E: має бути доступний системному обліковому запису без інтерактивного входу. Файл сценарію має залишатися в захищеній папці Program Files.

```powershell
$script = "$env:ProgramFiles\School Class Manager\Host\Backup-SchoolVM.ps1"
$action = New-ScheduledTaskAction -Execute 'powershell.exe' -Argument (
    '-NoProfile -NonInteractive -File "{0}" -VMName school-server -Destination "E:\SchoolBackups"' -f $script)
$trigger = New-ScheduledTaskTrigger -Daily -At '02:00'
Register-ScheduledTask -TaskName 'SCM backup' -Action $action -Trigger $trigger -User SYSTEM -RunLevel Highest -Force
Get-ScheduledTaskInfo -TaskName 'SCM backup'
```

Перевірте результат першого запуску за розкладом. Код `LastTaskResult` має дорівнювати 0, а на диску має з’явитися новий завершений каталог. Якщо політика хоста вимагає підпису сценаріїв, підпишіть перевірений файл сертифікатом адміністратора відповідно до цієї політики. Перед кожною копією на носії має вистачати місця для повного експорту. Видаляйте старі експорти лише після перевірки новішого.

## Перевірка відновлення

1. На резервному Hyper-V-хості підготуйте окремий каталог для відновлених дисків. У диспетчері Hyper-V виберіть **Імпортувати віртуальну машину**, укажіть завершений експорт і виберіть **Копіювати віртуальну машину** з новим ідентифікатором. Збережіть диски в новому каталозі.
2. **До першого запуску** від’єднайте мережевий адаптер копії від шкільної мережі. Для перевірки з тестовим ПК використайте приватний віртуальний комутатор. Робочий і відновлений контролери одного домену не мають одночасно з’явитися в одній мережі.
3. У консолі відновленої Ubuntu перевірте `systemctl is-active samba-ad-dc scm-panel`, `sudo samba-tool dbcheck --cross-ncs` та `curl --cacert /etc/scm-panel/lab-ca.crt "https://$(hostname -f):8443/healthz"`.
4. У приватній мережі вкажіть відновлений сервер як DNS тестового ПК. Перевірте вхід учителя, стан комп’ютерів у панелі, вхід тестового учня та вміст заздалегідь збереженого файла на H:. Запишіть дату копії та час, потрібний на відновлення.
5. Для справжньої заміни спершу від’єднайте несправний контролер. Поверніть відновленій VM початкову IP-адресу і тільки тоді підключіть її до шкільної мережі. Стан файлів, паролів та членства у групах відповідає часу копії. На клієнті з порушеною довірою перевірте `Test-ComputerSecureChannel` і відновіть приєднання з локального облікового запису адміністратора.

[Експорт та імпорт VM у Hyper-V](https://learn.microsoft.com/en-us/windows-server/virtualization/hyper-v/deploy/export-and-import-virtual-machines)

## Оновлення

1. Створіть копію VM. Підготуйте новий версійний архів і звірте його контрольну суму. Розпакуйте в окремий каталог `/opt/scm-install/<версія>` за порядком із першого встановлення. На чинному домені виконайте **лише** `sudo bash server/install-panel.sh` із нового комплекту.
2. Перевірте відповідь `/healthz` і вхід учителя. Сервер зберігає домен, файли, реєстрації та сертифікати. Новий MSI з’явиться у `NETLOGON\scm` під новою назвою. Зберігайте попередні MSI, доки вони призначені політикою.
3. Для пілотної групи призначте новий MSI так само, як під час першого встановлення. У властивостях пакета на вкладці **Upgrades** виберіть попередній пакет. Після перезавантаження пілотного ПК перевірте версію та новий звіт у панелі. Тоді поширте оновлення на клас.
4. Щоб зупинити невдале розгортання, припиніть призначення нового пакета. У груповій політиці можна вилучити призначений пакет із тих ПК, на які він уже потрапив. Після видалення нової версії призначте попередній MSI. Для повернення всієї системи до узгодженого стану використайте перевірену копію. Врахуйте зміни учнівських файлів після її створення.

Попередній EXE-агент із ручною реєстрацією зберігає параметри в `C:\Program Files\School Class Manager\Agent\config`. MSI встановлює виконуваний файл в окрему теку версії та зберігає доступ служби до попередніх параметрів. Для доменного розгортання додайте ПК до групи й застосуйте політику довіри до сертифіката. У першому звіті з доменним ключем панель перемикає запис ПК на доменну реєстрацію.

## Діагностика

| Що сталося | Що перевірити |
| --- | --- |
| Клієнт не знаходить домен | На ПК перевірте DNS і запит `Resolve-DnsName _ldap._tcp.dc._msdcs.ad.school.example -Type SRV`. В Ubuntu перевірте `ip -br -4 address` і час через `timedatectl`. |
| MSI не встановився | На клієнті відкрийте PowerShell адміністратора. Виконайте `gpresult /scope computer /r`. Перевірте членство **комп’ютера** у групі, шлях UNC до MSI та журнал Windows «Програма», джерело MsiInstaller. |
| Служба є, звіту немає | На клієнті перевірте `Get-Service ScmAgent`, сертифікат у сховищі **Local Computer**, доступність TCP 445 і 8443 та події `Get-WinEvent -FilterHashtable @{LogName='Application'; ProviderName='ScmAgent'} -MaxEvents 5`. На сервері виконайте `sudo systemctl start scm-enroll.service` і `sudo journalctl -u scm-enroll -u scm-panel -n 40`. |
| Панель не відкривається | Перевірте назву сайту, DNS і `sudo systemctl status scm-panel`. Увійдіть за доменним іменем сервера, яке вказано в сертифікаті. |
| Документи учня лишилися локально | У сеансі учня виконайте `gpupdate /target:user /force`, вийдіть і ввійдіть знову. `[Environment]::GetFolderPath('MyDocuments')` має вказувати на сервер. |
| Потрібно відкликати доступ комп’ютера | Видаліть його з `scm-agent-computers` командою `sudo samba-tool group removemembers scm-agent-computers 'CLASS-PC01$'`. Виконайте `sudo systemctl start scm-enroll.service`. Попередній запис лишиться в історії панелі, а доменний ключ втратить чинність. |

Служба `scm-tls.timer` щотижня перевіряє сертифікат панелі й поновлює його за 30 днів до завершення дії. Перевірте таймери через `systemctl list-timers 'scm-*'`. Шкільний кореневий сертифікат має окремий десятирічний строк. До його завершення розповсюдьте новий кореневий сертифікат через політику довіри, а потім перевипустіть сертифікат панелі.

Панель надає вчителям доступ до робіт усіх учнів цього домену. Спільний режим Windows (Shared PC) відображається у звіті. Агент цієї версії читає його стан. Налаштування режиму та видалення локальних профілів залишаються окремими адміністративними діями.
