# Перша робоча вебпанель

Панель працює на `school-server`: **https://school-server.school.test:8443** (також https://192.168.1.176:8443). Є вхід учителя/адміністратора, реальний список учнів, створення учня з особистою папкою H: та скидання пароля. Інші екрани старого мокапу поки не підключені до навігації.

## Перший вхід із Windows-клієнта

Під поточним доменним користувачем у звичайному PowerShell:

```powershell
Import-Certificate -FilePath '\\school-server.school.test\NETLOGON\school-lab-ca.cer' -CertStoreLocation Cert:\CurrentUser\Root
```

Це додає публічний сертифікат лабораторії до довірених для поточного користувача Windows. Джерело — доменна папка сервера; приватний ключ там не публікується. [Опис Import-Certificate від Microsoft](https://learn.microsoft.com/en-us/powershell/module/pki/import-certificate) пояснює використання `CurrentUser\Root`. Якщо Windows показує підтвердження імпорту, назва CA — `School Lab CA`.

SHA-256 сертифіката цієї домашньої лабораторії:

```text
BE:CF:C0:6E:1B:BF:F5:20:90:10:BF:05:3C:B0:4F:E9:CD:FD:FC:E9:2F:13:6A:38:43:5B:87:6F:0B:5F:AF:25
```

Відкрити адресу панелі в Edge або Chrome. Для першої перевірки можна ввійти як **Administrator**, використовуючи встановлений раніше пароль домену. Вводити лише ім'я облікового запису, без `SCHOOL\`. Пароль від Ubuntu для цього входу не підходить. Windows-сеанс може залишатися учнівським: права панелі визначаються окремим входом у браузері.

Для окремого вчителя, у приватному терміналі Ubuntu:

```sh
sudo samba-tool user create teacher1
sudo samba-tool group addmembers vchyteli teacher1
```

Пароль ввести приховано у терміналі. `teacher1` автоматично не створювався; створювати його слід лише один раз. Учитель не потребує Domain Admins. Вихід із панелі завершує вебсеанс; автоматичний строк сеансу — 20 хвилин.

## Вхід із Mac

2026-11-25 панель відкрилася на Mac за адресою https://192.168.1.176:8443. Mac не потрібно приєднувати до домену чи змінювати його DNS.

Початкову довіру до CA було обмежено SSL-адресою `192.168.1.176`. macOS приймає такий запис, але [Chromium ігнорує записи з `kSecTrustSettingsPolicyString`](https://chromium.googlesource.com/chromium/src/+/main/net/cert/internal/trust_store_mac.cc#112), тому Chrome показував `Not Secure`.

Додано довіру **лише до конкретного кінцевого сертифіката панелі** (`.local-backups/school-panel-server.cer`) у користувацьку в'язку ключів. Його SAN містить `192.168.1.176` та `school-server.school.test`, строк дії — до 2027-11-25. Загальну довіру до всіх сертифікатів CA не додано. Перевірка macOS успішна; користувач підтвердив скриншотом зникнення попередження Chrome та успішний вхід адміністратора.

Повторення з кореня репозиторію в терміналі Mac (macOS може попросити системне підтвердження):

```sh
security add-trusted-cert -r trustAsRoot -p ssl -k "$HOME/Library/Keychains/login.keychain-db" .local-backups/school-panel-server.cer
open 'https://192.168.1.176:8443'
```

Після додавання довіри повністю закрити Chrome через `⌘Q` і знову відкрити панель. Після перевипуску серверного сертифіката потрібно отримати перевірену нову копію та повторити імпорт. Керувати довірою можна через [Keychain Access](https://support.apple.com/en-euro/guide/keychain-access/kyca11871/mac). Для нової інсталяції створюється інший CA; наведений вище відбиток стосується лише поточного сервера.

## Робочий сценарій

1. У списку видно справжні `student1` і `student2`. Пошук і «Оновити» працюють із даними API.
2. «Додати учня»: увести унікальний логін (наприклад `student3`), прізвище та ім'я. Логін — малі латинські літери, цифри, крапка або дефіс, перший символ — літера.
3. Після успіху панель один раз показує згенерований пароль. Передати його учневі; кнопка «Зберіг дані» прибирає його з екрана. Паролі не зберігаються у браузерному сховищі або журналі операцій.
4. Новий учень отримує доменний акаунт, членство `scm-students`, каталог `/srv/school/home/<login>` з правами 0700 і `homeDrive=H:`. Для нових учнів UNC — `\\school-server.school.test\pupils`; Samba підставляє ім'я автентифікованого користувача у шлях. Наявні UNC student1/student2 залишаються чинними.
5. «Скинути пароль» потребує підтвердження й показує новий пароль один раз. Скидання не завершує відкриті Windows/SMB-сеанси. У перевірці Kerberos старий пароль відхилено; NTLM може тимчасово приймати попередній пароль через поведінку Samba, тому не вважати скидання миттєвим відкликанням усіх доступів.

За явним вибором користувача учнівські паролі максимально короткі: **7 символів**, мінімум поточної доменної політики. Формат — чотири вимовні латинські літери та три цифри, наприклад `Mepa234` (лише приклад, не пароль акаунта). Перша літера велика, решта малі; немає дефісів, `l`, `I`, `0`, `1`. Два склади й три цифри вибираються через `secrets.choice`; комбінації з логіном або частинами імені довжиною від трьох символів відкидаються. Формат застосовується до створення та скидання, не змінюючи наявних паролів. Політика домену не послаблювалась: великі/малі літери та цифри задовольняють увімкнену складність. Простір генератора до відкидання збігів — `80^2 × 8^3 = 3 276 800` (приблизно 22 біти): це суттєво слабший пароль, свідомо обраний заради простоти введення дітьми. Не використовувати для адміністраторів чи службових акаунтів. Якщо мінімальна довжина домену зросте, потрібно оновити генератор; цей формат прив'язаний до перевіреної лабораторної політики.

Якщо налаштування папки не завершилося після створення акаунта, він залишається вимкненим, а панель повідомляє про часткове виконання. Повторне створення не видаляє чи перезаписує наявний акаунт або каталог.

## Доступ учителя до учнівських файлів

У списку учнів натиснути **«Файли»**. Відкриється особиста папка H: вибраного учня: підпапки, назви, розміри, час зміни. Папку можна відкрити, повернутися на рівень вище та завантажити файл. Редагування, завантаження на сервер і видалення в цій версії відсутні. Вкладення завжди завантажується як файл, без виконання HTML у домені панелі.

Доступ мають адміністратор і члени `vchyteli`, до **всіх** звичайних учнів групи `scm-students`; поділ учителів за класами ще не реалізований. Членство та SID перевіряються при кожному запиті. Папки вчителів, адміністраторів і привілейованих акаунтів недоступні через ці маршрути. Учнівські SMB-права та Unix-права папок не розширюються.

Межі першої версії: файл до **20 МіБ**, не більше **2000 записів** в одній папці. Завантаження буферизується в пам'яті через JSON-міст; великі файли потребуватимуть окремого потокового механізму. Дозволені лише звичайні файли, що належать відповідному учневі та мають одне жорстке посилання. Символічні посилання, жорсткі посилання й спеціальні файли не показуються і не завантажуються. Кожна складова шляху відкривається через файловий дескриптор каталогу з `O_NOFOLLOW`; абсолютні шляхи й `..` відхиляються.

Маршрути: `GET /api/students/{login}/files?path=...` та `GET /api/students/{login}/download?path=...`. Імена з кирилицею, пробілами та `#` передаються через URL-кодування. API має `Cache-Control: no-store`; списки файлів прибираються з кешу вебпанелі при виході/закінченні сеансу та приховуються при відмові доступу.

`lab/panel-smoke.py` перевіряє доступ тимчасового вчителя до файлів тимчасового учня, точний вміст завантаження, вкладені папки, заборону анонімного доступу, виходу за межі папки, посилань, FIFO і файлів понад ліміт, а також негайне відкликання доступу після видалення ролі вчителя. Файли наявних учнів тест не змінює.

2026-11-26 файловий доступ розгорнуто на `school-server`. Пройдено 109 тестів .NET, 6 React-тестів, TypeScript/Vite, ARM64 publish та розширений HTTPS/Samba/SMB smoke-тест. Перший запуск smoke одразу після перезапуску сервісу випередив відкриття порту; інсталятор тепер чекає успішного HTTPS `/healthz` з перевіркою CA перед повідомленням про готовність. Перевірка API пройшла після запуску сервісу, тимчасові акаунти й файли прибрано.

## Реалізація й межі доступу

- React/Ant Design використовує API .NET; TypeScript-контракт генерується зі Swagger. Джерело даних — Samba, а не статичний мокап.
- Збережено `Scm.Core` / `Scm.Infrastructure` / `Scm.Api` і наявний `SudoRunner`. Новий `AccountName` описує справжнє ім'я AD; роль визначають групи. Старий `Login` збережено як невикористану в живій панелі модель. PR #3/#4 замінені поточним підходом без злиття їхніх гілок; рішення — у [checkpoint](checkpoint-2026-11-26.md).
- Вхід перевіряється Kerberos-автентифікацією LDAP зі шифруванням SASL. Ініціалізація Samba Credentials використовує `guess(lp)`, а потім явно задає ім'я/пароль і вимагає Kerberos. Порожні паролі відхиляються.
- Вебпроцес працює як `scm`, а не root. Через sudo дозволено лише `/usr/local/sbin/scm-directory` без аргументів. Структурований запит і секрети передаються через stdin; паролів у argv немає. Python запускається з `-I`.
- Обгортка заново перевіряє SID, активність та групи вчителя для кожної операції. Ціль скидання має бути у `scm-students`; учителі, адміністратори й привілейовані облікові записи виключені, зокрема за вкладеними групами/tokenGroups.
- Cookie має Secure, HttpOnly, SameSite=Strict. POST-запити вимагають antiforgery-токен, API відповідає з `Cache-Control: no-store`. Вхід обмежено п'ятьма спробами за хвилину з однієї IP-адреси. [Документація ASP.NET Core про antiforgery](https://learn.microsoft.com/aspnet/core/security/anti-request-forgery).
- Журнал створення/скидання: `/var/lib/scm-directory/journal.sqlite3`, root-only. Записує Started/Succeeded/Failed, виконавця, операцію й ціль без паролів. Журнал розміщено біля привілейованої операції, щоб вебпроцес не міг його редагувати.

## Повторення розгортання

Потрібні налаштовані Ubuntu 24.04, Samba, два початкові учні й папки з попередніх інструкцій. На хості збірки — .NET SDK 8 та Node.js 20 або новіший. Самодостатня публікація не потребує встановлення .NET SDK у VM.

З кореня репозиторію на **Mac M1**:

```sh
npm --prefix web ci
npm --prefix web run build
dotnet test --nologo -m:1
dotnet publish src/Scm.Api -c Release -r linux-arm64 --self-contained -o out/panel
COPYFILE_DISABLE=1 tar --no-xattrs -czf out/scm-panel.tar.gz -C out/panel .
```

На **Windows-хості Intel/AMD**, у PowerShell:

```powershell
npm --prefix web ci
npm --prefix web run build
dotnet test --nologo -m:1
dotnet publish src/Scm.Api -c Release -r linux-x64 --self-contained -o out/panel
tar -czf out/scm-panel.tar.gz -C out/panel .
```

Не змішувати ARM64 і x64 публікації в одному `out/panel`: для іншої архітектури використовувати чисту папку публікації. Windows-хост поки не перевірено. Ubuntu-команди встановлення однакові для обох архітектур; перед новим шкільним розгортанням замінити домашню IP `192.168.1.176` у `lab/install-panel.sh` для SAN сертифіката, якщо LAN-адреса інша. DNS-ім'я й realm у цих скриптах поки фіксовані для лабораторії.

На **будь-якому хості**, з кореня репозиторію:

```sh
multipass exec school-server -- mkdir -p /tmp/scm-panel-install
multipass transfer lab/scm-directory.py lab/setup-panel.py lab/scm-panel.service lab/install-panel.sh school-server:/tmp/scm-panel-install/
multipass transfer out/scm-panel.tar.gz school-server:/tmp/scm-panel.tar.gz
multipass exec school-server -- sudo bash /tmp/scm-panel-install/install-panel.sh /tmp/scm-panel.tar.gz
multipass exec school-server -- systemctl is-active scm-panel
```

Інсталятор зберігає попередні каталоги релізів у `/opt/scm-panel`, оновлює посилання `current`, не перевидає наявний CA, перевіряє sudoers, створює групи без повторного додавання членів та вмикає сервіс. Наявні паролі учнів не змінюються. Перший невдалий запуск до встановлення CA було виправлено перевіркою наявного членства в групі; повторне встановлення пройдено.

## Перевірки та поточний стан

На Ubuntu, через хост:

```sh
multipass transfer lab/panel-smoke.py school-server:/tmp/panel-smoke.py
multipass exec school-server -- sudo python3 /tmp/panel-smoke.py
```

Цей тест створює тільки власні тимчасові акаунти й видаляє їх у `finally`. Перевіряє HTTPS із довірою до CA, відмову анонімному доступу, CSRF, вхід учителя, список, створення, конфлікт логіна, скидання, перевірку нового/старого паролів через Kerberos, заборону учнівського входу, захист Administrator, запис/читання H: через SMB, заборону чужої папки, отримання публічного CA через NETLOGON, відкликання ролі вчителя та аудит. Очікується `PANEL_SMOKE_OK` і `DISPOSABLE_PANEL_ACCOUNTS_REMOVED`. Повідомлення LDAP про LOGON_FAILURE під час негативної перевірки старого пароля очікуване.

Перевірено 2026-11-25:

- 105 тестів .NET і 4 тести React пройдено; TypeScript/Vite та self-contained ARM64 publish успішні.
- Наскрізний тест на реальній Samba пройдено. Створення і скидання перевірялися лише на тимчасових учнях; student1/student2 та їхні паролі збережено.
- У Chrome перевірено вхід, список, створення, підтвердження скидання, показ результату й вихід; JavaScript-помилок не було. Тимчасовий браузерний профіль не мав CA, тому лише в цьому тесті ігнорувалася недовіра до сертифіката; окремий HTTPS smoke-тест перевіряв справжній CA. Перший вхід користувача з Windows ще очікується.
- Розгорнутий сервіс: `scm-panel`, порт 8443. Samba й панель працюють паралельно.
- Перший вхід Administrator на Mac виявив помилку: Samba повертала `Administrator`, а наступний запит списку відхиляв великі літери (`400 validation`). Виправлено нормалізацію імені актора перед перевіркою прав і поверненням сесії; SID та членство в групах залишаються обов'язковими. Виправлення встановлено у `/usr/local/sbin/scm-directory`; вже видані сесії також підтримуються. Перевірка нижче та повний HTTPS smoke-тест із великими літерами в імені тестового вчителя пройшли.
- Автоматичні резервні копії, імпорт CSV, масові операції та інші екрани відкладено за рішенням користувача.
- Поточні старі архіви домену не містять нових налаштувань панелі. Для повного відновлення самої панелі також потрібні її реліз/скрипти, `/etc/scm-panel` (CA й TLS-ключі), `/var/lib/scm-directory` (аудит) та за потреби `/var/lib/scm-panel/keys` (вебсеанси).

Перевірка регістру імені адміністратора без зміни доменних даних (на хості Mac або Windows):

```sh
multipass transfer lab/check-panel-admin.py school-server:/tmp/check-panel-admin.py
multipass exec school-server -- sudo python3 /tmp/check-panel-admin.py
```

Очікується `ADMIN_SESSION_OK`: список доступний з `Administrator`, `administrator`, `ADMINISTRATOR`, а підміна SID відхиляється.
