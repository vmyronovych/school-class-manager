# Перше розгортання в школі

Вам потрібні два комп’ютери. На серверному ноутбуці працюватиме Ubuntu у віртуальній машині (VM). Учнівський ПК увійде до домену. Агент встановлюється тільки на учнівські ПК. Для першого випробування достатньо одного.

## 1. Запишіть параметри школи

У прикладах нижче домен має назву `ad.school.example`, коротке ім’я — `SCHOOL`, сервер — `school-server`. Замініть домен на піддомен школи, яким ви керуєте. Це інструкція для створення нового домену. Якщо комп’ютери вже належать до чинного шкільного домену, узгодьте інтеграцію з його адміністратором до встановлення.

| Що визначити | Приклад |
| --- | --- |
| Стала IPv4-адреса VM і префікс мережі | 192.168.10.10/24 |
| Шлюз і чинний сервер DNS | 192.168.10.1 |
| Домен DNS і коротке ім’я домену | ad.school.example, SCHOOL |
| Ім’я сервера | school-server |
| Місце для повної копії VM | окремий зашифрований диск |

Зарезервуйте адресу VM або вилучіть її з діапазону DHCP. До переходу на новий DNS перевірте, що мережа школи дозволяє зв’язок між клієнтами та сервером. Для першого ПК DNS можна задати вручну. Після перевірки змініть параметри DHCP лише для мережі класу.

## 2. Підготуйте Windows-хост

Використайте підтримувану редакцію Windows із Hyper-V, апаратною віртуалізацією та дротовим Ethernet. Домашній тест проведено на Windows 10 Pro Education збірки 19043. Для шкільного використання виберіть ОС, яка отримує оновлення безпеки. [Вимоги Hyper-V](https://learn.microsoft.com/en-us/windows-server/virtualization/hyper-v/host-hardware-requirements)

1. Увімкніть компонент **Hyper-V** у вікні «Увімкнення або вимкнення засобів Windows». Перезавантажте хост.
2. У диспетчері Hyper-V відкрийте диспетчер віртуальних комутаторів. Створіть **зовнішній** комутатор на дротовому адаптері. Дозвольте основній ОС користуватися цим адаптером.
3. Створіть VM другого покоління з назвою `school-server`. Для пілота виділіть щонайменше 2 віртуальні процесори і 4 ГіБ пам’яті. Розмір диска VHDX доберіть за обсягом учнівських робіт і запасом на оновлення. Підключіть VM до зовнішнього комутатора.
4. Завантажте образ Ubuntu Server 24.04 LTS для AMD64. Підключіть ISO до VM. Для безпечного завантаження виберіть шаблон **Microsoft UEFI Certificate Authority**. [Образ Ubuntu Server](https://releases.ubuntu.com/24.04/)
5. Установіть Ubuntu. Укажіть ім’я сервера `school-server`. Створіть обліковий запис адміністратора Ubuntu (у прикладах — `operator`). Увімкніть OpenSSH Server. У налаштуваннях мережі задайте статичну адресу, префікс, шлюз і чинний DNS зі своєї таблиці.
6. У параметрах VM виберіть автоматичний запуск після завантаження хоста й коректне завершення роботи гостьової ОС під час вимкнення хоста. На ноутбуці вимкніть сон від мережевого живлення. Перевірте також дію закриття кришки.

У консолі Ubuntu перевірте ім’я, мережевий інтерфейс і доступ до репозиторіїв.

```sh
hostname -s
ip -br -4 address
ip route
sudo apt-get update
```

З іншого ПК у мережі класу перевірте SSH до адреси VM командою `Test-NetConnection 192.168.10.10 -Port 22`. Очікуваний результат — `TcpTestSucceeded: True`.

## 3. Установіть домен і панель

На Windows-хості відкрийте PowerShell у папці із завантаженими файлами. Звірте SHA-256 архіву з файлом контрольної суми, отриманим із довіреного джерела. Потім передайте архів до VM.

```powershell
Get-FileHash .\scm-0.2.0-amd64.tar.gz -Algorithm SHA256
Get-Content .\scm-0.2.0-amd64.tar.gz.sha256
scp .\scm-0.2.0-amd64.tar.gz operator@192.168.10.10:
ssh operator@192.168.10.10
```

В Ubuntu розпакуйте комплект. Створіть **окрему** копію файлу параметрів. Укажіть назву інтерфейсу з `ip -br -4 address`. Поле `address` містить адресу без префікса. `dns_forwarder` — адреса сервера DNS, до якого Samba пересилатиме зовнішні запити.

```sh
sudo install -d -m 0755 /opt/scm-install/0.2.0
sudo tar -xzf ~/scm-0.2.0-amd64.tar.gz --no-same-owner -C /opt/scm-install/0.2.0
cd /opt/scm-install/0.2.0
sha256sum --check --quiet SHA256SUMS
sudo cp server/site.example.json /etc/scm-site.json
sudoedit /etc/scm-site.json
sudo python3 server/first-install.py /etc/scm-site.json
```

Введіть новий пароль доменного облікового запису `Administrator` у прихований запит. Збережіть його у шкільному сховищі паролів. Установлення налаштує Samba, особисті папки учнів, перенаправлення документів і робочого стола, панель HTTPS та видачу ключів агентам. На завершення з’являться відповідь `"ok":true` і відбиток сертифіката школи. Збережіть відбиток для перевірки на інших комп’ютерах.

Якщо встановлення перервалося після створення домену, перевірте `sudo samba-tool domain info 127.0.0.1`. Для встановлення пароля скористайтеся `sudo python3 server/set-admin-password.py`. Для продовження встановлення панелі виконайте `sudo bash server/install-panel.sh` із каталогу комплекту. Повторне створення домену знищило б його ідентичність, тому перший сценарій зупиняється за наявності бази домену.

## 4. Приєднайте перший учнівський ПК

Потрібна редакція Windows, яка підтримує приєднання до домену. Підготуйте також локальний обліковий запис адміністратора для обслуговування поза доменом.

1. У параметрах IPv4 учнівського ПК задайте адресу VM як сервер DNS. Публічний DNS у полі додаткового сервера може завадити пошуку домену. За правильного налаштування Samba сама пересилає зовнішні запити.
2. Відкрийте PowerShell від імені локального адміністратора. Замініть домен на шкільний. Перевірте DNS, збережіть відкриті файли й приєднайте ПК до домену.

```powershell
Resolve-DnsName _ldap._tcp.dc._msdcs.ad.school.example -Type SRV
Add-Computer -DomainName ad.school.example -Credential (Get-Credential 'SCHOOL\Administrator') -Restart
```

3. Після перезавантаження перевірте `Test-ComputerSecureChannel`. Очікуйте `True`. Запишіть ім’я ПК з команди `hostname`. Щоб увійти під локальним обліковим записом, укажіть `.\ім’я`.

## 5. Призначте агент комп’ютерам

Один раз створіть групову політику на **адміністративному Windows-ПК**, приєднаному до домену. Установіть додатковий компонент **RSAT: Group Policy Management Tools** та відкрийте `gpmc.msc` з правами адміністратора домену. Для роботи консолі адміністративний ПК також має використовувати DNS домену.

1. У консолі створіть політику **SCM — Учнівські ПК** і зв’яжіть її з доменом. У розділі фільтрування безпеки приберіть право застосування для `Authenticated Users`. Додайте групу `scm-agent-computers` із правами читання та застосування. На вкладці делегування залиште для `Authenticated Users` право **читати** політику. До групи додавайте облікові записи комп’ютерів.
2. У редакторі політики відкрийте **Computer Configuration → Policies → Software Settings → Software installation**. Виберіть **New → Package**. Введіть повний мережевий шлях `\\school-server.ad.school.example\NETLOGON\scm\ScmAgent-0.2.0-x64.msi`. Виберіть **Assigned**. Так Windows встановить пакет до входу учня. [Розгортання MSI через групову політику](https://learn.microsoft.com/en-us/troubleshoot/windows-server/group-policy/use-group-policy-to-install-software)
3. Скопіюйте з тієї самої папки `school-ca.cer`. Звірте результат `Get-FileHash .\school-ca.cer -Algorithm SHA256` із відбитком, який показав сервер (двокрапки та регістр літер не впливають на значення). У цій політиці відкрийте **Computer Configuration → Policies → Windows Settings → Security Settings → Public Key Policies → Trusted Root Certification Authorities** та імпортуйте перевірений сертифікат.
4. В Ubuntu додайте перший ПК до групи. Нижче його ім’я — `CLASS-PC01`. Знак долара позначає обліковий запис комп’ютера. Одинарні лапки зберігають його в команді.

```sh
sudo samba-tool group addmembers scm-agent-computers 'CLASS-PC01$'
sudo systemctl start scm-enroll.service
```

5. Перезавантажте учнівський ПК у шкільній мережі. Якщо Windows відклала встановлення політики, виконайте від адміністратора `gpupdate /target:computer /force` та перезавантажте його ще раз. Для наступних ПК повторюйте лише приєднання до домену й додавання до групи. Список дозволених комп’ютерів оновлюється автоматично приблизно раз на хвилину.

Агент звертається до Samba під доменним обліковим записом свого комп’ютера й отримує його окремий ключ через зашифроване з’єднання SMB. Панель приймає звіти через HTTPS. Для цього способу кнопка ручної реєстрації в панелі не потрібна.

## 6. Відкрийте панель і прийміть перший ПК

На комп’ютері вчителя чи адміністратора встановіть довіру до того самого перевіреного `school-ca.cer`. На Windows для одного користувача можна виконати `Import-Certificate -FilePath .\school-ca.cer -CertStoreLocation Cert:\CurrentUser\Root`. Якщо це Mac, імпортуйте сертифікат у В’язку ключів, установіть довіру для SSL і налаштуйте розпізнавання доменного імені через шкільний DNS.

1. В Ubuntu створіть обліковий запис учителя й додайте його до групи. Команда попросить пароль у терміналі.

```sh
sudo samba-tool user create teacher01
sudo samba-tool group addmembers vchyteli teacher01
```

2. Відкрийте `https://school-server.ad.school.example:8443` за шкільним доменним іменем. Браузер має підтвердити довіру до сертифіката. Увійдіть як `teacher01`.
3. На сторінці **Комп’ютери** знайдіть учнівський ПК. Перевірте версію агента і час звіту. Залиште ПК на екрані входу. Приблизно через п’ять хвилин оновіть список і перевірте наступний звіт.
4. На сторінці **Учні** створіть тестового учня. Увійдіть у Windows як `SCHOOL\логін`. Збережіть файл у «Документах». У панелі відкрийте **Учні → Файли**. Перевірте, що файл можна завантажити, а інший учень не має доступу до цієї особистої папки.
5. До додавання решти класу перезавантажте Windows-хост сервера. Перевірте доступність DNS, панелі, учнівських файлів і новий звіт агента без входу адміністратора на хості. Створіть першу копію за [інструкцією з обслуговування](operations.md).
