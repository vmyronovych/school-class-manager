# Особисті папки двох тестових учнів

Продовження [налаштування Samba](lab-samba.md). Домен `school.test` працює, Windows приєднаний, перший вхід `SCHOOL\student1` уже перевірено. Команди всередині Ubuntu однакові для ARM64 VM на Mac і AMD64 VM на Windows-хості; шкільний хост ще не перевірено.

## Серверне налаштування

У терміналі **Mac або PowerShell Windows-хоста**, з кореня цього репозиторію:

```sh
multipass transfer lab/setup-student-homes.py school-server:/tmp/setup-student-homes.py
multipass exec school-server -- sudo python3 /tmp/setup-student-homes.py
```

Скрипт призначений тільки для лабораторного `school-server` у `SCHOOL.TEST`. Він вимагає наявного `student1`, створює `student2`, якщо його ще немає, і не змінює паролів наявних користувачів. Початковий випадковий пароль нового `student2` не виводиться й не зберігається в скрипті; власний пароль треба задати нижче.

| Учень | Папка на Ubuntu | UNC у Windows | Диск |
| --- | --- | --- | --- |
| `student1` | `/srv/school/home/student1` | `\\school-server.school.test\student1` | `H:` |
| `student2` | `/srv/school/home/student2` | `\\school-server.school.test\student2` | `H:` |

Кожна папка належить відповідному доменному UID і має права `0700`. Окремий параметр Samba `valid users` дозволяє підключення лише цьому учню. Папки приховані з переліку ресурсів (`browseable = no`), але обмеження доступу забезпечують права, а не приховування. Це ізоляція між учнями; адміністратор Ubuntu з root-доступом може керувати файлами.

У `/etc/samba/smb.conf` додається позначений блок; попередня конфігурація зберігається в `/etc/samba/smb.conf.before-student-homes`. Перед застосуванням виконується `testparm`, потім конфігурація перечитується без перезапуску VM. Скрипт не видаляє вміст папок і не змінює права вкладених файлів рекурсивно. Неочікувані власники, символічні посилання, наявні сторонні однойменні ресурси або відмінні атрибути домашньої папки зупиняють виконання для перевірки.

У записах AD задано `homeDrive=H:` та відповідний UNC у `homeDirectory`: це [атрибути домашнього диска Windows](https://learn.microsoft.com/en-us/windows/win32/ad/security-properties). Параметри доступу описані в [документації Samba](https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html). Наступний вхід у Windows має підключити диск. Літеру `H:` не повинен займати інший диск.

## Перевірка student1 у Windows

Зберегти роботу, **вийти з облікового запису** й увійти знову як `SCHOOL\student1`. Блокування екрана не створює новий сеанс. Mac та Ubuntu VM мають працювати й бути доступними в мережі.

Відкрити звичайний PowerShell під учнем, без запуску від адміністратора:

```powershell
whoami
net use H:
Set-Content -Path H:\student1-test.txt -Value 'Hello from student1'
Get-Content H:\student1-test.txt
Get-ChildItem '\\school-server.school.test\student2' -ErrorAction Stop
```

Очікується: `school\student1`, диск веде до `\\school-server.school.test\student1`, файл читається, остання команда дає **Access is denied / Відмовлено в доступі**. Помилка «шлях не знайдено» або «мережа недоступна» не доводить ізоляцію. Якщо H: не з'явився, зберегти вивід `net use` і перевірити власний UNC; не підміняти автоматичне підключення ручним до з'ясування причини.

## Пароль і перевірка student2

На **Mac або Windows-хості**:

```sh
multipass shell school-server
```

У відкритому терміналі **Ubuntu**:

```sh
sudo samba-tool user setpassword student2
```

Приватно ввести новий пароль двічі; не додавати пароль у команду, чат чи репозиторій. Очікується `Changed password OK`. Не створювати student2 повторно.

На **Windows-клієнті** вийти зі student1, увійти як `SCHOOL\student2`, дочекатися першого налаштування профілю. У звичайному PowerShell:

```powershell
whoami
net use H:
Set-Content -Path H:\student2-test.txt -Value 'Hello from student2'
Get-Content H:\student2-test.txt
Get-ChildItem '\\school-server.school.test\student1' -ErrorAction Stop
```

Очікується власний диск student2, успішний запис/читання і відмова в доступі до student1. Після цього повторно ввійти як student1 і переконатися, що його файл `H:\student1-test.txt` зберігся, а `student2-test.txt` у його H: відсутній. Робочий стіл і «Документи» залишаються локальними: серверними є лише файли, які зберегли на H:.

## Фактичний стан, 2026-11-25

- Скрипт застосовано на домашній VM і успішно запущено повторно.
- student1 має UID 3000021, student2 — 3000022; обидві папки мають режим 0700.
- Під Unix-ідентичністю кожного учня перевірено створення, читання й видалення тимчасового файла у власній папці. Спроби перегляду й запису в чужу папку отримали `Permission denied`. Тимчасові файли видалено.
- Перевірено `valid users`, дозвіл запису у власний ресурс і атрибути AD `homeDrive` / `homeDirectory` для обох користувачів. `samba-ad-dc` активний.
- Користувач підтвердив появу H: після повторного входу під student1 та збереження власного файла. При відкритті чужого UNC student2 Провідник запропонував інші облікові дані; доступ у поточному контексті student1 не надано. Це спостереження з Провідника, а не зафіксований код помилки PowerShell.
- Потім користувач підтвердив успішний вхід під student2, створення власного файла та відсутність доступу до файлів student1. Базовий сценарій двох учнів із приватними папками перевірено на Windows користувачем.
- Повторний вхід назад під student1 і перевірку збереження його файла після зміни користувача окремо ще не підтверджено.
- Ручну резервну копію папок збережено на Mac; відновлення видаленого тестового файла, вміст, метадані й ізоляцію перевірено в окремому каталозі, також після повернення копії з Mac. Команди та обмеження — [lab-backup.md](lab-backup.md). Окремий комплект домену та серверне випробування відновлення також готові — [lab-domain-recovery.md](lab-domain-recovery.md). Розклад і реальне перемикання Windows-клієнта ще не перевірено.
