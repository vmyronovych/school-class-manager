# Робочий результат — 26 листопада 2026

Цей документ фіксує межу між перевіреною домашньою лабораторією й подальшим розгортанням у школі. Основна гілка репозиторію — `main`.

## Підтверджено

| Сценарій | Доказ / межі |
| --- | --- |
| Mac M1 → Multipass → Ubuntu 24.04 ARM64 | `school-server`, Samba 4.19.5, домен `school.test`, LAN `192.168.1.176`; реальний Windows-клієнт приєднано до домену, secure channel справний |
| Учнівські акаунти й H: | Входи student1/student2, створення файлів і взаємна ізоляція перевірені користувачем |

| Файли в панелі | Перегляд особистих папок і завантаження, автоматичні перевірки ролей та небезпечних шляхів, користувач бачить свої роботи |
| Folder Redirection | Після виправлення `Version=100` Windows повертає серверний UNC для MyDocuments; після перезапуску та входу student2 користувач також бачить Documents/Desktop у панелі |
| Резервні копії | Ручна копія файлів; ізольоване відновлення попереднього комплекту домену з перевіркою SID/DNS/SYSVOL/Kerberos/SMB. Поточна панель, ключі TLS й журнал аудиту ще не входять у повний перевірений сценарій відновлення |

Старі попередження gpupdate з помилкою параметра усунено виправленням заголовка GPO. Подальший запит виходу для застосування політики під час входу — очікувана поведінка. Локальний профіль, AppData і Downloads залишаються на Windows; перенаправлення не робить вхід ефемерним.

## Що публікуємо

- `lab/` та послідовні інструкції: VM, домен, учнівські папки, панель, перенаправлення, ручні копії/відновлення.
- Живі API/SPA та вузький Samba bridge: автентифікація, учні, створення/скидання, читання файлів, аудит.
- Тести, знеособлені фікстури, CI та актуальні пояснення стану.
- Політику простих семисимвольних учнівських паролів як явний вибір користувача; її обмеження описано в `lab-panel.md`.

Не публікуємо `.local-backups/`, сертифікатні приватні ключі, паролі, дані учнів, діагностичні звіти з H:, результати збірки й `web/.vite/`. Локальний Vite-кеш зберігається на диску, але ігнорується Git.

## Наступні кроки

1. **Shared PC на одному тестовому Windows-клієнті.** Обрано PowerShell через штатний MDM Bridge із виконанням під SYSTEM; не потрібен Intune. Скрипт має явно налаштовувати доменні входи, політику очищення й винятки для потрібних адміністративних/особистих профілів. Спочатку інвентаризація локальних даних; окремий тестовий учень. Приймання: вихід → локальний профіль прибрано → повторний вхід → серверні Documents/Desktop та вміст робіт збережені. Виміряти час входу. Shared PC ще **не ввімкнено**, самописного видалення C:\Users не додавати.
2. **Повторюване розгортання на шкільному Windows-хості.** Перевірити редакцію Windows, RAM/диск, віртуалізацію та Ethernet; підготувати Ubuntu x64. Винести домашні адреси/імена й початкові тестові акаунти в конфігурацію. Перевірити мережу з фізичного учнівського ПК. Shared PC застосовується до учнівських ПК, не до Windows-хоста серверної VM.
3. **Перед реальними учнівськими даними — актуальне відновлення.** Розширити комплект на конфігурацію й стан панелі, TLS, ключі cookie та аудит; перевірити свіжий комплект у відокремленому середовищі. Потім повернутися до розкладу копій, ротації, окремого фізичного носія та відновлення на x64. Автоматичні копії наразі відкладені, не вважати їх перевіреними за результатом ручної копії.
4. **Невеликий класний пілот.** Окремий учитель без Domain Admins, кілька учнів/ПК, повторні входи, файли, скидання пароля, поведінка при недоступності сервера. Лише після цього — масове створення, класи та доступ учителів лише до своїх класів.

Джерела для обраного наступного кроку: [Shared PC — способи налаштування](https://learn.microsoft.com/en-us/windows/configuration/shared-pc/set-up-shared-or-guest-pc), [поведінка очищення](https://learn.microsoft.com/en-us/windows/configuration/shared-pc/shared-devices-concepts). PowerShell/PPKG/Intune — способи налаштування одного механізму Windows, а не різні типи профілю.

## Відомі межі

- Шкільний Windows-хост, x64 runtime, другий фізичний учнівський ПК і навантаження класу не перевірені.
- Усі члени vchyteli бачать усіх звичайних учнів scm-students. Межі завантаження: 20 МіБ на файл, 2000 записів на папку; потокового завантаження немає.
- Папки потребують доступного сервера; Offline Files для учнівських share вимкнено. AppData/Downloads не перенаправлені.
- Лабораторні скрипти не універсальні й очікують поточні імена та структуру. Старі Pi-скрипти не є поточним способом розгортання.
- `npm audit` на момент checkpoint повідомляє 5 записів: source-map-js, Vite, Vitest, @vitest/mocker, tinypool. Для частини потрібне major-оновлення Vitest. Оновлення build/test toolchain — окремий найближчий технічний крок; не запускати dev/test сервери на зовнішньому інтерфейсі. Робоча панель віддає зібрану статику через Kestrel, без Node/Vite/Vitest на сервері; це не замінює усунення повідомлених вразливостей.
